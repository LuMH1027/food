# UI redesign plan

Kind: software, an existing functional consumer lunch assistant. This is the application itself, rather than a marketing landing page.

Deal: split; Funnel pairing with platform CJK fallback; brand palette generated by `start.mjs brand`: #f5f3ed / #22362b / #2c503c. The existing green brand is retained, with warm paper and higher text contrast. Round 10/16/24 control/panel/dialog family. No WebGL, scroll scenes, carousels, or marketing sections: the user's priority is an immediately usable application on phones and computers.

## Fact sheet and voice

- User: one person choosing office lunch. Main action: 就吃这份.
- Inputs: taste, excluded ingredients, budget, light cooking, staple requirement.
- Facts: 16 simulated meals; local preference/history storage; no real orders or payments.
- Voice: direct, practical Chinese, short labels. The same word for each action and state; no invented reviews, nutrition metrics or AI-confidence scores.

## Layout

- Desktop ≥1200: compact intro, 304px preferences column, image/text split recommendation, two alternative rows and yesterday memory. Equal outer edges for header, workspace, history and footer.
- Desktop 900–1199: same preferences column with image above recommendation details.
- Tablet 600–899: recommendations first; preferences move into a native modal. Side-by-side photo/details remain readable.
- Phone <600: one column, preference summary opens bottom sheet. Alternatives are full-width rows; every button and switch has a ≥44px tap target. Native dialog handles focus trap, Escape and restoration. Safe-area padding and 16px text inputs.
- 320px: compact brand and stacked heading; no horizontal overflow.

## Motion

Use unchanged Taste Skill motion.css and motion.js under their MIT license: single intro entrance, button press/hover. Linked alternatives lift 2px and images zoom within a clipped frame. No ongoing motion; reduced motion keeps the full interface readable.

## Scope adaptations

The skill's one-screen hero, one-screen footer, decorative moment and section marketing recipes would delay the user's core task. Preserve compact application sections and functional dialogs instead. This is an explicit adaptation to the user's request to optimize an existing usable Demo for mobile and desktop. Do not claim that landing-page structure checks pass; record them separately from functional and accessibility checks.

All four food photographs are licensed Unsplash stand-ins. The page footer and details state this; simulated meal names, shops and prices remain the authorized mock data.

## User refinement

The user explicitly requested fewer colors, fresh light colors, no dark fills, no fluorescent accents, and less explanatory copy. The final page uses #fafbf7 paper, white surfaces and #e1ebdc low-saturation green actions. Remove the brand subtitle, decorative note, marketing eyebrow, merchant line, recommendation badge, repeated reason title and toggle descriptions. Keep short actionable labels and put extended explanations in details/about.

User additionally authorized online reference research. See docs/product-notes.md for four verified official sources. Implement a bounded sentence-to-preferences input, preserving all existing exclusions and refusing unrecognized exclusions. This new user-directed iteration supersedes the prior gate round limit; no prior checker result is described as a pass.
