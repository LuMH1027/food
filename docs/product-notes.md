# 产品参考与设计取舍

核对时间：2026-11-26。来源是各产品公开官网与可直接操作的页面，不将营销主张作为本 Demo 的效果数据。

| 参考 | 实际观察 | 在本 Demo 中的应用 |
| --- | --- | --- |
| [Eat This Much](https://www.eatthismuch.com/) | 官网可直接填写条件生成计划；生成后支持整天、单餐局部重选 | 先筛选后推荐，只换当前一餐；补充一句话输入降低填写成本 |
| [Samsung Food](https://samsungfood.com/) | 公开介绍偏好与限制、食谱收藏、按周规划，并提供移动与网页入口 | 让今日推荐与午餐记录连起来；手机、平板与电脑按使用情境调整布局 |
| [KptnCook](https://www.kptncook.com/) | 官网明确每天提供 3 份精选食谱，突出少量选择与餐食图片 | 一份重点推荐加至多两份不同主菜备选，避免无尽菜单 |
| [Mealime](https://www.mealime.com/) | 公开页面分别展示饮食类型、过敏、排斥食材和份数；官网同时有 2026-10-21 停运公告 | 参考其偏好分类，不依赖其在线服务；忌口先排除，再处理口味排序 |

这些产品多面向做饭或营养计划。本题的办公室外卖午餐场景只保留决策有关的部分，不扩展购物清单、做菜步骤、社交或热量目标。

## 相比最初版本的改进

1. **更短的输入路径：** 用户可以输入“清淡点，不要香菜，30元以内”。本地解析为口味、忌口和预算后，展示识别结果并立即更新推荐。原有忌口不会被删除，无法识别的忌口会明确拒绝部分更新。
2. **减少选择疲劳：** 只突出一餐，两份备选使用不同主菜。菜品级别的替换不要求重新填写偏好。
3. **有记忆的推荐：** 按主菜而非套餐名称去重。昨天吃了鸡腿饭，今天鸡腿沙拉也不会出现。
4. **条件透明：** 预算与忌口是硬约束；口味是排序偏好。如果硬约束下没有对应口味，会直接提示，不伪造“高度匹配”。没有任何符合条件的餐食时，用户自己决定调整预算或偏好。
5. **浅色与短文案：** 按用户要求使用白色、浅灰绿与低饱和浅绿按钮；删除标语、商家描述、重复推荐标签和同义说明。餐图与推荐决定界面重点，完整边界说明收在“关于 Demo”和食材详情。
6. **真正适配设备：** 电脑并排设置与推荐；手机、平板先看结果，偏好按需打开。原生对话框提供键盘与焦点行为，输入字号 16px，按钮与开关触控区域至少 44px。

## AI 与数据边界

AI 辅助完成需求分析、竞品研究、交互与界面设计、代码开发、模拟菜单及测试。一句话入口是有明确范围的本地规则解析，**没有在线大模型调用**；如未识别输入会报错，不伪造模型思考或置信度。

菜品、商家和价格为用户授权的模拟数据。4 张 Unsplash 餐图均为示意，不声称对应商品实拍。无真实下单、支付、热量测量或过敏安全承诺。数据仅保存在本地浏览器。

## 验证

18 项推荐与输入解析测试，以及 1440、1024、820、768、390、320px 浏览器回归。覆盖横向溢出、图片、≥44px 点击区域、一句话输入、未知忌口、底部面板、键盘焦点、空结果、昨日去重、当天确认、刷新恢复和实时窗口切换。

Taste Skill 的文案、截图、性能与门禁脚本已实际执行。首轮发现的文字对比度、触控区域和阅读层级问题已修正。最后一个门禁结果是 `GATE: OPEN 25 (rounds used up)`：保留的主要差异来自营销落地页的整屏 hero、整屏 footer、固定 section 高度、装饰性 moment、特定 `.wrap` 模板和两条文字起始线要求。应用的表单、侧栏、餐食卡片和紧凑记录区不遵循这些营销模板，不将其表述为完整门禁通过。原始结果保存在 `.taste-skill/gate.json`，未设置豁免。

首轮性能检查：桌面与手机均无 FAIL、无破损请求，布局偏移为 0；主机繁忙影响计时，保留为 WARN。随后又增加了明确图片尺寸与独立小缩略图，避免小卡片下载大图。具体时延不作为产品承诺。
