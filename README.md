# 午饭有着落 · Lunch, sorted.

一个为独自吃午饭的办公室用户设计的午餐推荐 Demo。使用 AI 辅助完成需求分析、交互设计、模拟菜单、前端开发和验证。

**体验地址：** https://lumh1027.github.io/food/

## 核心问题

用户每天反复浏览外卖菜单，决策成本高；推荐还需要兼顾口味、忌口、连续两天主菜不重复、少油少炸和主食。目标是让用户快速确定一餐，而不是展示更多菜单。

## 方案思路

先选择口味、忌口和预算，再获得一份重点推荐、至多两份不同主菜的备选。每一份推荐都展示具体理由。用户可换一道、查看全部已知食材，或点击“就吃这个”记录今天午饭。支持补记昨天、删除记录、持久化偏好和刷新恢复。

- **硬约束：** 按食材精确标签严格排除忌口，控制预算；开启少油时仅保留标记为少油且非油炸的菜品，开启主食时必须包含主食；昨天吃过的同一道主菜连同其他套餐一起排除。
- **排序：** 匹配口味数优先，随后偏好少油和主食，再考虑价格。口味是软偏好，不匹配时明确提示“换个口味试试”。
- **决策减负：** 一份重点推荐，至多两份不同主菜的备选。没有结果时不自动放宽忌口与历史约束，提示调整预算与偏好。
- **记录闭环：** 每天一条午餐记录，修改今天会覆盖当天记录；昨天记录参与次日去重，使用浏览器本地日期，支持跨月跨年。

## 1 分钟体验路径

1. 选择“家常、清淡”，勾选“香菜”，预算设为 35 元。
2. 看推荐理由，点击“换一道”或备选卡片，再打开食材详情。
3. 点击“补记昨天”，选择“香煎鸡腿”：鸡腿饭和鸡腿沙拉均会被排除。
4. 点击“就吃这个，开饭”，看到确认提示和今天的午餐记录；刷新后记录仍保留。
5. 把预算降至 15 元，查看无匹配结果时的处理。

## 取舍与边界

- 使用 16 份本地模拟菜单和可解释规则，没有在线大模型调用，无 API Key 和后端依赖。AI 用于辅助制作产品；个性化推荐本身无需模型推理。
- 偏好和最近 60 天记录仅保存在当前浏览器 localStorage，不跨设备同步，无账号登录。存储不可用时可继续当次体验。
- 所有价格、商家均为模拟，价格已含模拟配送费，无下单、支付或真实配送功能。
- 忌口按已知食材标签精确匹配，不推断同义词，不覆盖未知配料和交叉接触，不承诺过敏安全。
- “少油”是模拟菜品的烹饪方式标签，不代表实测营养数据。
- 餐图为餐食氛围示意，不代表对应菜品；Unsplash 图片已本地保存，不依赖外链加载。字体加载失败时使用系统中文字体。

## 手机与电脑界面

按 [Taste Skill](https://github.com/Leonxlnx/taste-skill) 优化：统一品牌色、字号、留白、按钮、焦点与动效。保留实际工具的紧凑布局，不添加营销页的整屏介绍或滚动特效。

- 900px 以上：偏好面板与推荐并排；1200px 以上主推荐使用左右图文布局。
- 600–899px：先展示推荐，偏好在原生对话框中调整，适配平板。
- 600px 以下：单列推荐，偏好使用底部面板；输入字号 16px，按钮和开关点击区域至少 44px，支持安全区。
- 偏好面板支持 Escape、背景点击关闭、原生焦点约束；旋转设备或拖动窗口时会自动移动回适当位置。
- 微交互动效来自 Taste Skill 的原始 motion 层；其 MIT 许可在 `assets/motion/LICENSE`。减少动态效果偏好下保留静态内容。

浏览器回归脚本：本机安装 Chrome，执行 `npm install --no-save playwright`，另一个终端执行 `npm start`，然后执行 `npm run test:browser`。脚本验证 1440、1024、820、768、390、320px 六种宽度、图片加载、点击区域、偏好面板、焦点、空结果、历史持久化和动态窗口切换。

## 提交用简短说明

**核心问题：** 一个人吃午饭，每天在外卖菜单里反复挑选，花时间却难决定，还要兼顾口味、忌口和避免重复。

**方案思路：** 用“偏好筛选 → 一份重点推荐与两份备选 → 确认并记录”的短流程降低决策成本。忌口先排除、预算不超标，默认少油不炸且含主食；记住昨天的主菜，今天换个花样，并给出具体推荐理由。用 AI 辅助完成产品设计与开发，模拟数据即可完整体验，无需登录。

现在也支持一句话选餐，例如“清淡点，不要香菜，30元以内”。该入口采用有范围的本地规则解析，遇到无法识别的忌口会提示手动添加，不会静默放宽条件。界面按要求收简为白色与低饱和浅绿，电脑并排操作，手机底部面板操作。
